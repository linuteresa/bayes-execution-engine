## Fixed

### 1. The ownership fence could be silently absent — `core/graph.py`
A caller passing a saver and an `attempt_id` but no `checkpoint_callback` got no fence *and*
no published recovery reference, so `job.checkpoint_ref` stayed `None` and the next attempt
restarted from scratch. Both halves of "durable recovery" failed with no error. The two
existing guards covered the other pairings; this one was open. Worker mode is now
all-or-nothing.

No test covered it — every test in `test_fenced_checkpointer.py` passes a callback.

### 2. `MAX_PROMPT_CHARS` had two legal ranges — `core/runtime.py`, `core/graph.py`, `app.py`, `service/api.py`
`app.py` and `service/api.py` read it with `maximum=1000000`; `core/graph.py` took the
`100000` default. `MAX_PROMPT_CHARS=200000` passed validation at the API boundary and then
failed *every* job inside the engine. The ceiling now lives beside the parser as
`MAX_PROMPT_CHARS_CEILING`, because a limit's legal range is a property of the limit, not of
the call site.

### 3. `with_allowlist` would split the fence — `persistence/fenced_checkpointer.py`
The class did not override it, so LangGraph's base implementation returned `copy.copy(self)`.
On a shallow clone `_cancelled` and `_thread_id` rebind independently, so a lease loss seen
through the clone would leave the original still publishing. LangGraph does call this
(`_internal/_serde.py:57` via `pregel/main.py:864`); it is dormant only because
`_serde_allowlist` defaults to `None`. Now re-wraps the derived delegate and shares one
fence.

### 4. Raw `os.getenv` in the module that imports the parser — `core/graph.py`
`float(os.getenv("EXECUTOR_TEMPERATURE", "0.7"))` bypassed `core/runtime.py`, so a bad value
failed per-job inside `build_llm` instead of at startup. Routing it through `positive_float`
removed the module's last raw `os` use.

### 5. Dead parameter that misled about provenance — `eval/harness.py`
`metadata_from_rows(rows, *, dataset_spec=...)` never read `dataset_spec`. Four tests passed
`dataset_spec="bundled"` and were silently ignored, so the tests read as if provenance spec
were controllable. Parameter and the four call-site arguments removed.

### 6. Dead parameter and stale docstring — `nodes/llm_executor.py`
`_count_distinct(samples, sim, same_answer)` used `samples` only for `len(samples)`, which is
`len(sim)` by construction. Its docstring still described the numeric-signature rule that had
moved into `_similarity_matrix`, sending readers to the wrong function.

### 7. Production code contorted for test fakes — `nodes/llm_executor.py` + 2 test files
`build_embeddings() if deadline is None else build_embeddings(timeout=...)` was a no-op in
production — the default *is* `None`. It existed because three test doubles were zero-argument
lambdas. **An agent flagged this as dead code; removing it broke three tests, which proved the
real defect was in the fakes.** The doubles now match the real signature and the branch is gone.

Also removed: `AttemptCheckpointer = FencedCheckpointer`, an alias with zero references whose
comment claimed it was retained for callers that do not exist.

## Deferred — and why

These are real. They were not applied because each changes behaviour, spans more than the
reviewed diff, or needs a design decision that is yours.

### A. Two numeric grammars disagree about equality — **highest priority**
`core/numbers.py` (new, `Fraction`-exact, unit-aware) sits beside `eval/grading.py`'s
pre-existing float parser with `rel_tol=1e-6`. They already disagree in both directions:

| input | `core/numbers.py` | `eval/grading.py` |
|---|---|---|
| `\frac{3}{4}` | two claims `(3, 4)` | `0.75` |
| `50%` | `1/2` | `50.0` |
| `1e400` | raises `ValueError` | silently dropped |

So a LaTeX sample and a decimal sample get similarity forced to 0.0 — *lowering measured
confidence* — while the grader scores both correct. **This repo exists to calibrate confidence
against correctness, and its two inputs use different definitions of "same number."**

Fix: make `eval/grading.py` a consumer of `core/numbers.py` — move `_LATEX_FRACTION` into it,
have `numeric_match` compare the last `(Fraction, unit)` claim with tolerance, delete grading's
private regex and float parser. Deferred because it will move the published benchmark numbers
and should be a deliberate, re-measured change.

### B. The grader is accumulating per-benchmark English heuristics
`_numeric_answer_span` carries a GSM8K-shaped rule ("can buy … with the remaining \$X"), plus
`_UNCERTAIN`, `_NEGATED`, `_BOXED`, `_LATEX_FRACTION`. `GRADING_VERSION` is already at 3 and
this PR ships `LABEL_AUDIT.json` re-scoring 500 questions.

Tuning a grader against observed misses moves headline calibration numbers without the model
changing. The deeper fix is the input contract: `_prompt_for` returns the bare question, so ask
for a delimited final answer and grade only that span. **This one is a methodology decision, not
a cleanup.**

### C. Cancellation is enforced per call site, not structurally
`check_deadline` counts: planner 0, replanner 2, executor 2, llm_executor 5. A worker that
loses its lease during planning burns up to `MODEL_OUTPUT_ATTEMPTS` full LLM calls before
`_guarded`'s post-node check fires; the replanner checks before its retry loop but never
inside it. Deadlines are fine everywhere (enforced inside `bounded_model`) — only cancellation
leaks. Deeper fix: `bounded_model(model, config)` calls `check_deadline` itself, making every
model invocation guarded by construction.

### D. Error codes come from an isinstance ladder plus substring sniffing
`core/graph.py:216`. Model-caused and infrastructure-caused failures that raise bare
`ValueError` all collapse to `invalid_request`: a malformed numeric literal from the model, an
embedding-server outage, and an unavailable recovery checkpoint are reported identically, so
clients cannot tell retry-worthy from fatal. Fix: make the exception class the source of the
code and raise the right class at the point of failure.

### E. `Job` stores three fields for one fact — `persistence/job_store.py:44`
`attempts == len(attempt_ids)` and `attempt_id == attempt_ids[-1]`, all three mutated in
lockstep in both backends and all three serialized, so a torn write is representable. Keep
`attempt_ids`; derive the others as properties. Deferred: it changes the persisted schema.

### F. The model-output retry loop is duplicated
`nodes/planner.py:24` and `nodes/replanner.py:113-127` — eight structurally identical lines
that have already drifted into two shapes (`return`-in-`try`/`continue` versus
`break`/`for...else`; local variable versus mutating `payload["input"]`).

### G. The timeout clamp exists three times
`core/llm.py:37`, `core/llm.py:67`, and inside `bounded_model`. They differ in argument order
and in whether they check finiteness, and a model built by `build_llm(timeout=…)` then passed
through `bounded_model` is clamped twice by two implementations.

### H. ~32 of ~34 env reads still bypass `core/runtime.py`
Across 12 modules. Separately, `eval/provenance.py:144-155` hand-maintains its own list of
settings to snapshot, which will drift the first time a setting is added or renamed — and a
drifted provenance record is a silently wrong one. Deeper fix: a typed registry declared once.

## Also noticed, not filed

- `numeric_values` (`core/numbers.py`) and `write_rows` (`eval/harness.py`) have no production
  callers left — only tests.
- `SQLiteJobStore.prune`'s `job_ids=None` branch is reachable only from a test.
- `nodes/llm_executor.py` hardcodes `"Re-check: "` twice while `nodes/replanner.py` defines
  `RECHECK_PREFIX` for the same string.
- `FencedCheckpointer` leaves 16 base-class methods unforwarded. Most raise
  `NotImplementedError` (loud, therefore safe), but `prune`, `copy_thread` and
  `delete_for_runs` would make a *capable* delegate look incapable. Nothing calls them on a
  checkpointer today.
